# Open questions and device tests

This page collects everything the other pages leave unverified and says which device test would close each item. It is a work list, not a record of results: no test below has been run. A gap is an item that a page marks Not tested, or that rests only on notes, on a single observation or on a record that no longer exists. There are 100 gaps (27 High, 73 Low) and 14 conflicts between records that no measurement has settled. A gap that several pages share appears once, in the section where its test is easiest to run, and its Item cell names the other pages; each section ends with a pointer to the shared gaps that affect its page. IDs (`G01` onward) run across the whole page. Priority High means the gap blocks a common use of the unit and Low means an edge case; where the page-level lists rated one shared gap differently (the display wait with Live started first, G04; the stop-sending timings, G64; the display light-on-glass latency, G65), the higher rating is kept. The first word of each statement under "What is known" is its evidence label as defined in the [README](../README.md#evidence-labels); session IDs (`S01` to `S14`) are defined in [09-sessions.md](09-sessions.md) and record-ID citations (`R012:45`) are explained in [10-sources.md](10-sources.md). Every test says what to send or do, on which port and in which MIDI mode where that applies, and what to record. The last section lists the unresolved conflicts.
