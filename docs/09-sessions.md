# 09 - Test sessions

This page defines the test sessions in which the Push 3 unit was measured, and gives each one a stable ID (`S01` to `S14`). It is the only place where host, operating system, firmware, mode, port, tool and Live state are stated per session. The other pages of this spec cite a session by its ID (for example `S03`) and cite raw evidence as a record ID and line number (`R012:45`, see page 10). A fact that carries a session ID inherits every column of that session's row; where a column varies inside a session, the notes below the table list the blocks.

## Unit, sessions and time

All records concern one Push 3 unit: one USB serial (8 characters, serial redacted; read on macOS in S09, `R002:9`) is on record and no record names a second unit, so use of the same unit throughout is the working assumption, not a verified fact. A session is one host on one JST calendar date (a run past midnight is dated by its start, S10); blocks a, b, c inside a session are separate runs on that host and date whose conditions differ. The only exceptions are S12, S13 and S14: each shares host and date with an earlier session (S02, S03 and S08 in turn) and is kept apart because its tool, ports and conditions match no block of that session, so a fact citing S02, S03 or S08 would inherit columns that do not hold for it; see "Sessions added in review (S12 to S14)" below. Dates and times are JST (UTC+9) unless marked UTC or `Z`; the log kinds that use UTC are listed under the table.

## Firmware

What is known. The notes label the unit "firmware 1.5.4": `R001:4` and `R001:137` (macOS, 2026-10-01/02), `R007:1` (2026-10-01), and a code comment in a source file of the UE5 test host (`R168:49-50`; "[Windows PC] FW 1.5.4", host name replaced, citing `R007`). No record shows where "1.5.4" was read (for example a photo of the Setup > Software tab), so the label is a note-taker's statement, not a captured reading. The only value read from the unit is the Device Inquiry reply (26 bytes, `F0 7E 01 06 02 00 21 1D 69 32 03 00 01 00 5B 00`, four serial bytes (redacted), `00 03 01 14 04 F7`): software bytes `01 00` (1.0) and build bytes `5B 00` (build 91). It is byte-identical on every read: 2026-10-01 (S01), 2026-10-02 (S02 on Windows; S03 on macOS, as Live's own request), 2026-10-03 (S04) and 2026-10-08 (S11).

What is not known. No record maps "1.5.4" to "sw 1.0 build 91", and neither maps to Ableton's published "Push 2.4.6" (the current software on 2026-10-08 per the compiled official catalogue, `R018:3`); three numbering schemes are in use and no source relates them. The firmware or the Device Inquiry was not read in S05, S06, S07, S08, S09 or S10, and "1.5.4" was never stated for a Windows session. Whether the unit's firmware changed between the read dates is not recorded; nothing contradicts an unchanged firmware and nothing proves it. A fact in another page that carries "1.5.4" is true as a label for S01 and S03 only; a fact from any other session has no firmware reading except where the column above gives a Device Inquiry date.
